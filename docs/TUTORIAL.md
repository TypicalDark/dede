# dede tutorial — five tiers

This walkthrough teaches every feature of dede by analysing five flat x86-64
samples of increasing difficulty. The later tiers **rewrite their own code at run
time** — exactly the self-decrypting/polymorphic behaviour dede is built to peel
apart. The samples are generated by `dede-forge` (source in
`src/samples/tiers.cpp`), and `tests/test_tiers.cpp` verifies each one behaves as
shown here, so this guide can never drift from reality.

```sh
./build.sh                 # build (see README)
./build/dede-forge /tmp    # writes /tmp/tier1.bin .. /tmp/tier5.bin
./build/dede /tmp/tier1.bin   # load a tier; type `help` for all commands
```

Every sample loads at guest address `0x1000`, which is where `rip` starts.

---

## Tier 1 — arithmetic loop · *the basics*

**Teaches:** `dis`, `step`, `regs`, `bp`, `run`, `where`, `cfg`.
The program sums 5+4+3+2+1 into `rax` with a loop, then halts.

```
dede> dis 0x1000 6
=> 0x1000:  mov rax, 0
   0x1007:  mov rcx, 5
   0x100e:  add rax, rcx
   0x1011:  dec rcx
   0x1014:  jne 0x100e
   0x1016:  hlt
dede> step 2                 # single-step two instructions
=> 0x100e:  add rax, rcx   [tick 2]
dede> regs
rax = 0x0   rcx = 0x5   ...  rip = 0x100e   flags = 0x0   [tick 2, paused]
dede> bp 0x100e              # breakpoint on the loop body
breakpoint #1 @ 0x100e
dede> run
stopped at 0x100e () tick 5
dede> cfg 0x1000             # the control-flow graph (code flow)
CFG of 0x1000: 3 blocks, 3 edges
  loc_1000  (2 insns)
      --fallthrough--> loc_100e
  loc_100e  (3 insns)
      --taken--> loc_100e        # the loop back-edge
      --not-taken--> loc_1016
  loc_1016  (1 insns, terminal)
```

Let it finish with `run` a few times (or remove the breakpoint with `rp del 1`);
`reg rax` reads `0xf` (15). This is the whole debugger loop in miniature.

## Tier 2 — call + stack · *functions and the stack*

**Teaches:** `callgraph`, `stack`, stepping over a `call`, `cfg`.
`main` loads `0x15` (21), calls a helper that doubles it, and halts with `rax = 42`.

```
dede> callgraph 0x1000
2 function(s), 1 call edge(s):
  sub_1000 (2 blocks)
  sub_1010 (1 blocks)
  0x1007 -> 0x1010              # main calls the helper
dede> bp 0x1010                 # break inside the helper
dede> run
dede> stack 3                   # telescope the stack: the top slot is the return addr
  0x777f8 <- rsp : 0x100c       # returns to just after the call
```

Set a breakpoint past the call and `run` to see `rax` become `0x2a` (42). `cfg
0x1010` shows the one-block helper.

## Tier 3 — self-decrypting stage · *unpacking + time-travel*

**Teaches:** `scan`, the W^X trigger, watching code decrypt itself, re-disassembly,
`decompile`, and stepping **backwards**.
A stub at `0x1000` xors an encrypted "stage 2" at `0x2000` into real code and jumps
to it.

```
dede> scan 0x1000 40
1 finding(s) from 0x1000:
  [crypto/notice] 0x1013  xor by immediate (decrypt stub?)  (xor al, 0x5a)
dede> dis 0x2000 3           # before running, stage 2 is garbage
   0x2000:  adc bl, byte ptr [rbp - 0x655a4b66]
   0x2006:  pop rdx
   0x2007:  scasb al, byte ptr [rdi]
dede> run
stopped at 0x2007 (hlt) tick 53
dede> dis 0x2000 2           # after running, the real code is revealed
   0x2000:  mov rax, 0xc0ffee
=> 0x2007:  hlt
dede> decompile 0x2000 8
void sub_2000() {
    rax = 0xc0ffee;    // mov rax, 0xc0ffee
    hlt;
}
dede> back 1                 # time-travel: step one instruction backwards
=> 0x2007:  hlt   [tick 52]
dede> goto 0                 # rewind to the very start — stage 2 is encrypted again
```

Tip: `rp wx` sets a run point that fires the instant a written page is executed —
set it before `run` to stop exactly when stage 2 reveals itself.

## Tier 4 — anti-analysis · *transparency*

**Teaches:** `scan` (anti-vm + timing), `transparency on`, conditional branches.
The program times itself with `rdtsc`, checks the CPUID hypervisor bit, and branches
to a "detected" path (`rax = 0xDEAD`) or an "ok" path (`rax = 0x600D`).

```
dede> scan 0x1000 20
2 finding(s) from 0x1000:
  [timing/warning]  0x1000  rdtsc timing check  (rdtsc)
  [anti-vm/warning] 0x1007  cpuid (hypervisor/vendor probe)  (cpuid)
dede> transparency on         # forge a clean, bare-metal environment
transparency ON
dede> run
stopped at 0x1016 (hlt) tick 7
dede> reg rax
rax = 0x600d                  # took the 'ok' branch — the sample sees no VM/debugger
```

The `rdtsc` here reads a smooth, deterministic clock and `cpuid` reports no
hypervisor bit, so the sample never reaches its "detected" code. See
[TRANSPARENCY.md](TRANSPARENCY.md) for the full list of checks defeated.

## Tier 5 — multi-stage: decrypt + syscall + mutate · *everything at once*

**Teaches:** `scan`, decryption, `capture` (the Wireshark/Charles analog),
syscall MITM, and time-travel — combined.
The stub decrypts a stage 2 that performs a `write` syscall.

```
dede> capture on              # record the guest's external interactions
dede> run
dede> capture list
  #0 [t=107] 0x200e  write(0xc0ffee, 0x2011, 0x0)
1 transaction(s)
dede> reg rdi
rdi = 0xc0ffee                # the decrypted stage 2 really ran
```

**MITM** — rewrite the syscall's result and keep replay deterministic. In a script
or the GUI, bind a mutating macro to a `syscall` run point (see
`tests/test_capture.cpp` / [NETWORK_CAPTURE.md](NETWORK_CAPTURE.md)):

```cpp
RunPoint rp; rp.type = RunPointType::Syscall;        // any syscall
u64 id = engine.add_run_point(std::move(rp));
auto m = std::make_shared<Macro>(); m->mutating = true;
m->callback = [](IDebugController& c){ c.write_reg(Reg::Rax, 0x1337, "mitm"); };
engine.bind_macro(id, m);
engine.run();     // the syscall now "returns" 0x1337 — and because the edit is an
                  // injected event, seek(0) then replay reproduces it exactly.
```
