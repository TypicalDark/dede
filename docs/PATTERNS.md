# Design patterns in dede

The architecture rests on a deliberate pattern spine, not pattern decoration: each
pattern is here for a concrete decoupling or testability job. This catalogue surveys
the whole pattern universe — the GoF 23, concurrency and architectural patterns,
enterprise patterns, and C++ idioms — and maps each to a site in this codebase, or
records why it does not belong here. Knowing where *not* to apply a pattern is part
of the design.

## Implemented (23)

Load-bearing in the current tree.

| Pattern | Family | Where | What it buys us |
|---|---|---|---|
| **Abstract Factory** | GoF Creational | disasm/core — a per-Arch ArchSupport factory keyed on the Arch enum | types.hpp states verbatim that a new arch is 'a new Abstract-Factory branch'; a per-Arch factory produces the mutually-consistent family — Capstone-configured Disassembler, asmjit-style Assembler, interpreter semantic tables, reg-name maps. Today only Arch::X86_64 has a concrete branch. |
| **Adapter** | GoF Structural | disasm — CapstoneDisassembler implementing IDisassembler (recurs across decompiler/introspection/backends) | capstone_disassembler.cpp is the sole TU including <capstone/capstone.h>, translating cs_insn into structured DecodedInsn and releasing csh in its destructor; the same object-adapter shape recurs for the Ghidra IDecompiler, the LibVMI introspection adapter, and the Unicorn/KVM backends. |
| **Facade** | GoF Structural | session — AnalysisSession, the single entry point for shell and Luau | AnalysisSession orchestrates ExecutionCore, the TimelineManager caretaker, the disassembler, the macro dispatcher, transparency, decompiler and introspection behind attach/step/run-to/snapshot/rewind/decompile/introspect; the session State machine lives behind this same face. (session library not yet implemented.) |
| **Proxy** | GoF Structural | core — MemoryProxy implementing the same read/write/permissions surface as common::GuestMemory | memory_proxy.hpp interposes on every guest access to enforce page permissions, record dirty pages / W^X, emit MemRead/MemWrite to Observers, and (for Unicorn/KVM) marshal bytes to the owning engine; additionally ADD a virtual-proxy StateMemento handle that lazily rebuilds full state from the nearest sparse snapshot plus replay only on dereference. |
| **Memento** | GoF Behavioral | replay — StateMemento (CpuState + MemorySnapshot); ExecutionCore originator, TimelineManager caretaker | memento.hpp/memory.hpp — opaque snapshot, friend ExecutionCore, only tick() exposed; the caretaker stores one and hands it back without inspecting it, and COW pages make each capture O(resident pages) pointer bumps. |
| **Observer** | GoF Behavioral | core — IEventSink/Event in event.hpp; ExecutionCore is the subject | ExecutionCore emits Event for Step/MemWrite/Cpuid/ExecWrittenPage through IEventSink and never learns who listens; subscribers are the macro/run-point dispatcher, shell and decompiler. NullEventSink is the default; a typed subscribe(EventKind,sink) filter is the natural extension. |
| **State** | GoF Behavioral | session — AnalysisSession state machine (Idle/Running/Paused/Recording/Replaying) behind ISessionState | design-named; each state implements guarded step()/resume()/record() with on_enter/on_exit — Replaying walks TimelineManager, Recording appends each Command, Idle rejects mutations with a Result error — keeping the Facade free of mode-flag branching. (session library not yet implemented.) |
| **Strategy** | GoF Behavioral | core — IExecutionBackend (interpreter | Unicorn | KVM); IDisassembler/IAssembler are further instances | backend.hpp — ExecutionCore holds a unique_ptr<IExecutionBackend> and single-steps purely through step()/read surface, so swapping the in-tree interpreter for Unicorn/KVM is one construction-time choice with no core change; disassembler.hpp/assembler.hpp implement the same seam for decode/encode. |
| **Chain of Responsibility** | GoF Behavioral | transparency — the ITransparency chain in core/transparency_iface.hpp | build the concrete chain CpuidForge->RdtscForge->SidtForge->MsrForge->IoForge; each inspects ProbeRequest::kind, the first that can answer sets ProbeResult.handled and stops, else delegates. ExecutionCore holds one ITransparency* (chain head) defaulting to NullTransparency. |
| **Command** | GoF Behavioral | macro — ICommand(execute/undo): StepCommand, WriteRegCommand, WriteMemCommand, PatchCommand, SetRunPointCommand | design-named; each command captures its inverse state at execute() time (prior register value, overwritten bytes / MemorySnapshot of touched pages) so undo() is exact; a Macro is vector<unique_ptr<ICommand>>, replay re-runs execute() in order, step-back pops and calls undo(). (macro library not yet implemented.) |
| **Interpreter** | GoF Behavioral | script — the run-point condition grammar (and the shell mini-language), nodes with interpret(Context&) | design-named; the sharpest instance is the conditional-breakpoint grammar — terminals RegRef/MemDeref/Imm, nonterminals Cmp/And/Or/Not — evaluating against {CpuState,GuestMemory} so a run point fires only on e.g. 'rax==0 && [rsp]>0x10'. The embedded Luau engine is a third-party VM, not an instance of this pattern. |
| **Flyweight** | GoF Structural | common — shared_ptr<GuestPage> COW across GuestMemory and every snapshot; plus a DecodedInsn intern cache in disasm | memory.cpp page_for_write / use_count()>1 shares GuestPage across the live map and every snapshot with COW on first write, so N ring-buffer mementos cost O(resident pages). ADD the purest extra Flyweight: a decode cache interning immutable DecodedInsn keyed by instruction bytes so code re-executed across the timeline is decoded once. |
| **Null Object** | Behavioral relative | core — NullEventSink (event.hpp) and NullTransparency (transparency_iface.hpp) | both are implemented and load-bearing — ExecutionCore defaults its IEventSink* and ITransparency* to them so it runs headless with no hot-path null branch; extend with a NoopCommand to pad the undo stack at snapshot boundaries and a NullBackend for disassembly-only sessions. |
| **Layers** | Layered / POSA | whole build — the per-subsystem library DAG rooted at common | common/types.hpp states the strict DAG verbatim and the one-library-per-subsystem layout realizes it (common->disasm->core->{replay,transparency,macro,decompiler,introspection,script}->session->shell). Enforce by making each target_link_libraries point only downward and adding a CI include-direction check. |
| **Dependency Injection** | Creational relative (IoC) | core/session — ExecutionCore and AnalysisSession constructors | constructor-inject the ExecutionBackend (Strategy) and GuestMemory into ExecutionCore, the transparency chain into the backend, and the whole subsystem graph (core, TimelineManager, Decompiler, Introspection, ScriptEngine) into the AnalysisSession Facade. This is the backbone that makes every Strategy/Adapter/Proxy swappable and the replay/transparency logic unit-testable with fakes; implied by 'pluggable backend' but never named. |
| **Registry** | Creational relative | macro — the run-point registry; plus a shell/script verb->Command-factory table | the design's named run-point registry is this — a map from guest Addr/id to run points (break/watch/condition + callback) the single-step loop consults each tick to dispatch to subscribers. ADD a second instance: a verb->Command-factory table that backends and commands self-register into at static-init. Differs from Repository below by being name-lookup + self-registration rather than a storage-hiding collection API. |
| **Event Sourcing** | Fowler / DDD | replay — TimelineManager + the injected-event log | make the injected-event log the authoritative record — append every non-deterministic input and mutating-macro effect (rdtsc value, syscall result, injected reg/mem write) keyed by Tick, and define restore(tick) = nearest full StateMemento<\=tick replayed forward through the log. injected_event.hpp already logs mutations, so this formalizes the framing; the ring buffer of fine-grained mementos plus sparse snapshots become the standard snapshot optimization over the event log. |
| **Composite** | GoF Structural | macro — MacroCommand : Command holding vector<unique_ptr<Command>> | MacroCommand::execute() runs children in order and undo() undoes them in reverse, so a recorded macro is itself a Command and the run-point registry, dispatcher and TimelineManager treat a single step and a whole macro uniformly; the decompiler's P-code/AST tree walked by the Visitor is the system's second Composite. |
| **RAII** | Resource Management | disasm CapstoneDisassembler and every C-library adapter (future Unicorn/KVM, Ghidra, LibVMI, Luau lua_State) | wrap each raw handle in a tiny member type (struct CsHandle{ csh h{}; ~CsHandle(){ if(h) cs_close(&h); } }) and replicate one-handle-per-adapter for lua_State, uc_engine and the Ghidra handle, so a close can never leak on an error path; the project's COW/Result<T> ethos is already RAII, this extends it to the C boundaries and lets each Adapter obey Rule of Zero. |
| **Prototype** | GoF Creational | macro — a virtual Command::clone() | add clone() to the Command base so a recorded macro (list of unique_ptr<Command>) re-runs many times without move-consuming the originals, and so the undo stack can snapshot a command's captured parameters — a polymorphic clone through a base pointer that C++ value semantics alone cannot give; the 'clone the world' case (CpuState + COW memory) is the Memento, not this. |
| **Visitor** | GoF Behavioral | decompiler — IAstVisitor over the P-code/AST node hierarchy, each node exposing accept() | design-named; each node dispatches accept(IAstVisitor&) to visit(ConcreteNode&), so passes (pretty-printer, constant folding, dead-code elimination, taint) are visitor classes added without editing every node type; a smaller second instance visits disasm Operand variants (Reg/Imm/Mem) for the interpreter's operand resolution. |
| **Template Method** | GoF Behavioral | decompiler AbstractPass::run() and the interpreter backend's instruction cycle | a non-virtual AbstractPass::run(Function&) does on_enter(); for(node: fn) visit(node); on_exit(), with visit() the pure-virtual hook ConstantFoldingPass/DeadCodePass fill; the same shape fits the interpreter's step() skeleton (fetch via proxy -> DecodeCache lookup -> dispatch -> emit -> advance rip/tick) with a protected virtual execute_decoded(DecodedInsn&). |
| **Pipes and Filters / Pipeline** | POSA structural + Concurrency | decompiler — the P-code/AST pass sequence | model the 'passes over P-code/AST' as IDecompilerPass{ Program transform(Program) } assembled into a PassPipeline (bytes -> P-code lift -> const-fold/simplify -> control-flow recovery -> type propagation -> AST -> pseudocode); each filter is testable alone, the Visitor is how a filter walks its AST, and running stages on separate threads is an optional later throughput win. Merges the Pipeline and Pipes-and-Filters proposals. |

## Candidate additions (49)

Surveyed as sound extensions as the tool grows (several become relevant only once
the Unicorn/KVM backends, the Ghidra decompiler, or worker-thread batch analysis
land). Listed so the growth path is explicit rather than discovered ad hoc.

| Pattern | Family | Where | What it buys us |
|---|---|---|---|
| **Hexagonal / Ports and Adapters** | Ports & Adapters | session + core — AnalysisSession ports, every external tool behind a port interface | the de-facto dominant style — driving ports (shell CLI, Luau, test harness), driven ports (IExecutionBackend, IDisassembler, IAssembler, ITransparency, future IDecompiler/IIntrospection); the existing NullEventSink/NullTransparency are Cockburn's 'driven by tests with no real devices', so the whole core already compiles and unit-tests with stub adapters and zero third-party libs — just formalize the port list. |
| **Microkernel / Plugin** | POSA structural | core — ExecutionCore + IExecutionBackend (and the wider external-tool plug-in set) | ExecutionCore owns machine state and the single-step loop but delegates all CPU semantics to a plug-in backend via make_builtin_backend(), with Unicorn/KVM slated behind the same interface.  promote the ad-hoc make_* functions to one BackendRegistry (name->factory + capability flags) and reuse the socket for disasm/decompiler/introspection plug-ins. |
| **Interceptor** | POSA2 | transparency — ITransparency and the core's probe sites | exactly the 'interceptors' the design names — the core turns each cpuid/rdtsc/sidt/rd-wrmsr/io probe into a ProbeRequest at a fixed point and dispatches to ITransparency::handle, where a forger overrides via ProbeResult.handled. Keep the Chain-of-Responsibility as the dispatch mechanism; each forger is an interceptor keyed on ProbeRequest::Kind and ProbeRequest.tick is the determinism context. |
| **Rule of Zero / Rule of Five** | Special Member Functions | project-wide; common GuestMemory/MemorySnapshot/CpuState and core StateMemento | these types already declare no special members and the COW Memento depends on it (snapshot() is a cheap copy of a std::map<u64,shared_ptr<GuestPage>>). Codify it as the house rule: whenever a class acquires a non-RAII resource, push the handle into a small RAII wrapper (see RAII) rather than hand-rolling Rule of Five, so zero classes in the tree need the full five. |
| **Factory Method** | GoF Creational | core — ExecutionBackend::make_memory_proxy() / make_cpu_view() | InterpreterBackend returns a proxy over the COW GuestMemory while Unicorn/KvmBackend each return a proxy bridging their own hypervisor memory model; ExecutionCore calls backend->make_memory_proxy() without knowing the concrete type, so a new backend never touches core. Distinct from Abstract Factory — one product chosen by the backend subclass, not an arch-keyed family. |
| **Builder / Fluent Interface** | GoF Creational + idiom | disasm Assembler and macro RunPoint construction | make the asmjit-style Assembler a fluent builder (asm.mov(Reg::Rax,0x10).ret().encode()) separating 'what instructions' from 'how encoded' — today assemble() is text->bytes; and give the run-point registry a fluent builder for its many optional fields: registry.add(RunPoint::at(0x401000).on(EventKind::MemWrite).when(pred).oneShot().run(macro)). Merges the Builder and Named-Parameter/Fluent-Builder proposals. |
| **Bridge** | GoF Structural | core — ExecutionCore (abstraction) over an ExecutionBackend implementor | ExecutionCore (single-step/run loop, event emission, memory wiring) holds a backend implementor; this becomes Bridge rather than plain Strategy once the abstraction side also grows a hierarchy (an Arch-parameterised core, or stepping-vs-free-run cores) over the same backend hierarchy — exactly the Arch-by-engine matrix the Abstract Factory populates. |
| **Decorator** | GoF Structural | core — WatchpointMemory/LoggingMemory wrapping the guest-memory interface; TracingBackend/CoverageBackend wrapping IExecutionBackend | WatchpointMemory tests each read/write against armed watchpoints before delegating to the inner memory, and LoggingMemory stacks on top, adding debugger features without touching GuestMemory or the Proxy; the same stackable shape fits IExecutionBackend, keeping ExecutionCore oblivious to optional instrumentation. Distinct from the CoR transparency interceptors. |
| **Extension Object** | Structural relative | core — IExecutionBackend::queryExtension<T>() | engine-specific capabilities (IHardwareWatchpoints, IDirtyPageTracking, ISnapshotAcceleration, ISmcDetection) live on extension objects a backend returns only when supported, instead of forcing every engine to stub them on the one interface; run-points, transparency and the timeline query for a capability and degrade gracefully (the interpreter vs KVM diverge sharply here). |
| **Iterator** | GoF Behavioral | replay — a bidirectional TimelineCursor over TimelineManager's ticks | a TimelineCursor with next()/prev()/seek(Tick) yields the reconstructed {CpuState, GuestMemory view} at each tick, hiding whether a tick comes straight from a fine-grained memento or is rebuilt from the nearest sparse snapshot plus forward replay; model it as a C++20 bidirectional range so range-for and std algorithms work directly. |
| **Specification** | Behavioral relative | macro — run-point/conditional-breakpoint predicates and Observer event filtering | Specification<EvalCtx>::isSatisfiedBy over {CpuState, GuestMemory, Event} with And/Or/Not combinators; a RunPoint fires only when satisfied (PcEquals(0x401000) && RegEquals(Reg::Rax,0) && PageWasWritten()). Because specifications are composable and serializable they drop into the macro/injected-event log and can be the output of the Interpreter's condition grammar — keeping composition (Specification) separate from parsing (Interpreter). |
| **Servant** | Behavioral relative | common/replay — StateDiff/StateSerializer servants over CpuState, GuestMemory, MemorySnapshot | types.hpp keeps value types behaviour-free, so a RegisterDiff servant takes two CpuState& for the timeline's per-step delta view, a MemoryDiff servant takes two MemorySnapshots to list dirtied pages, and a StateSerializer servant persists a StateMemento — preserving the layering rule that common stays a leaf with no I/O or diffing dependencies. |
| **Service Locator** | Creational relative (IoC) | script/shell — a SessionServices locator exposed to Luau and the shell interpreter | expose the session's subsystems through one lookup object scripts and shell commands query by name (dede.memory, dede.decompiler, dede.timeline) so scripts bind late to whatever the host offers; justified ONLY at this dynamic script boundary — inside the C++ core prefer DI, since a Service Locator there hides dependencies and defeats testability. |
| **Object Pool** | Creational relative | common/replay — a GuestPage free-list behind COW and the memento ring-buffer slots | back GuestMemory::page_for_write's COW clone with a free-list of 4 KiB GuestPage objects returned when a ring-buffer memento is evicted — stepping and recording churn millions of pages, so pooling removes malloc traffic on the hot path; the design's fixed-slot ring buffer is itself a memento pool, so reuse the slot storage rather than reallocating per retired instruction. |
| **Active Object** | POSA2 Concurrency | decompiler — the Ghidra-native adapter behind IDecompiler | decompile(addr) enqueues a request on the adapter's own worker thread and returns a Future immediately instead of blocking the shell for seconds; the worker drains its queue serially (Ghidra/JVM state is not re-entrant) so the decompiler view and the single-step loop stay responsive while pseudocode is produced. |
| **Monitor Object** | POSA2 Concurrency | core/common — a single BlockingQueue<T> | one BlockingQueue<T> (private mutex + not-empty/not-full condition_variable, every push/pop locking) reused for both the engine->shell Event queue and the shell->engine Command queue, becoming the single serialization point once the run loop moves off the shell thread rather than ad-hoc mutexes scattered across subsystems. |
| **Thread Pool** | Concurrency | decompiler + introspection — common::ThreadPool for batch analysis | submit one job per function for whole-program decompilation / CFG recovery and per-structure jobs for LibVMI OS-list walks, collecting their Futures; it bounds parallelism, reuses threads across many short passes, and is the executor onto which the decompiler Active Object schedules its serial jobs. |
| **Half-Sync/Half-Async** | POSA2 Concurrency | session + core + shell — the overall process architecture | an async layer (the ExecutionCore run loop plus Ctrl-C / async backend interrupts), a sync layer (shell command handling and Luau scripts that run to completion), and a queueing layer (the Event and Command queues) between them; the load-bearing constraint is keeping execution and replay OUT of the async layer so the step loop stays single-threaded and determinism is preserved. |
| **Producer-Consumer** | Concurrency | core — IEventSink->shell (events up) and shell Command->core (commands down) | the engine thread produces Event objects the subscribers (shell, macro recorder, decompiler) consume at their own pace, and symmetrically the shell produces Command macros the engine consumes between steps; decoupling via the bounded queue lets a fast run loop emit without stalling on a slow UI, turning the Observer fan-out into a queued hand-off. |
| **Guarded Suspension** | Concurrency (Lea) | core — the ExecutionCore run loop gated by the session State machine | when the session State is Paused the engine thread waits on a condition variable until the state becomes Running or a step command arrives, rather than spinning; the guard 'state==Running || pending step' is signalled by the shell thread's resume/step commands, a cooperative suspend/resume layered on the State pattern. |
| **Scoped Locking / RAII locks** | POSA2 Synchronization | every mutex-guarded method (BlockingQueue, TimelineManager, backend registries) | hold every mutex through std::scoped_lock/std::unique_lock so it releases on all paths including the DedeError exceptions the codebase throws off the hot path; it is the mandatory baseline the moment any lock exists and matches the project's existing RAII ethos — manual lock/unlock is never acceptable here. |
| **Thread-Specific Storage** | POSA2 Synchronization | disasm — per-worker Capstone handle / DecodeCache | csh handles are not safe to share across threads, so give each analysis-pool worker its own handle and decode scratch (optionally its own DecodeCache) via thread_local, letting the hot decode path run lock-free for read-mostly batch decoding instead of putting a shared cache under Monitor-style locking. |
| **Balking** | Concurrency (Lea) | session — AnalysisSession Facade + macro Commands, keyed on session State | methods invalid in the current State return immediately with a Result error instead of blocking or queueing — step() while Replaying, record() while already Recording, take_snapshot() while one is in flight; each Command/Facade entry checks state and balks, pairing with the State machine for fast predictable rejection rather than the indefinite wait Guarded Suspension imposes. |
| **Future/Promise** | Concurrency | decompiler (IDecompiler) + introspection (LibVMI query) results | async jobs hand back a std::future the shell awaits or polls — IDecompiler::decompile(addr)->future<Pseudocode>, LibVMI->future<OsView>; it is the result-handle half of the Active Object / Thread Pool story, turning a blocking call into 'request now, collect later' without exposing threads to callers. |
| **MVP (MVC/MVVM family)** | Presentation separation | shell CLI front end (and a future TUI) over AnalysisSession as model | AnalysisSession is the model, a ShellView renders CpuState/DecodedInsn/timeline, and the shell + script interpreter is the presenter mapping typed verbs to session calls and refreshing the view when the IEventSink Observer fires; keeping view logic out of the command interpreter makes a later TUI or GUI a drop-in additional view with no duplicated logic. |
| **CQRS** | Fowler / Young | macro Command write side vs the session/proxy read API | split AnalysisSession into a journaled write side (every mutation is a recorded undoable Command) and a side-effect-free query side (cpu snapshot, disasm, memory read) that never perturbs the event stream or timeline; MemoryProxy already embodies the split (peek/poke 'silent access for tooling' vs observed read/write) — make that distinction explicit across the whole session API so 'every state change is a recordable Command' becomes an enforceable invariant feeding Event Sourcing. |
| **Reflection / metadata** | metaobject protocol | script + macro — one CommandRegistry metadata table | build one table describing every macro Command and session verb (name, parameter types, help text), then generate the Luau bindings, shell dispatch, tab-completion and `help` from it instead of maintaining each by hand; reg_name/reg_from_name in types.hpp is the same idea in miniature, so extend it so scripts can enumerate registers and commands reflectively. |
| **Repository** | Fowler PoEAA | macro run-point store and replay TimelineManager over mementos | make the run-point registry a RunPointRegistry with add/remove(id)/at(addr)/enabled_at(addr)/all() so the hot dispatch path asks 'run point here?' without knowing the backing store (page-hashed map, interval tree); TimelineManager is the same pattern over StateMementos keyed by Tick ('nearest snapshot<\=tick'). | **Unit of Work** | Fowler PoEAA | macro — the recorded-macro executor | the executor accumulates the Commands it has applied and, on a mid-macro fault or user abort, calls their undo() in reverse so the machine is all-or-nothing, optionally bracketed by one StateMemento for one-shot rollback; this makes the 'mutating macros' safe to apply during live analysis, and is realized via the Scope Guard below. |
| **Scope Guard** | Resource Management | macro transactional execution; also the MemoryProxy silent-access seam | after each sub-command's execute() push an on-exit guard that calls its undo(), and commit() only once the whole list succeeds, so a macro that faults halfway auto-rolls-back (the mechanism behind Unit of Work); second concrete use — a guard that swaps the core's IEventSink to NullEventSink and restores it while tooling peek/pokes, so the observed event stream and W^X state are never perturbed even if the snapshot throws. |
| **Copy-and-Swap** | Special Member Functions | core — ExecutionCore::restore(const StateMemento&) backed by GuestMemory::swap() | give GuestMemory a noexcept swap() (swapping the two std::maps and the dirty vector) and implement restore as build the restored CpuState + GuestMemory from the memento then swap them in; because the only mutating step is noexcept, a restore that throws while reconstructing leaves the live machine — and the timeline the analyst is navigating — completely untouched. |
| **PIMPL / Compiler Firewall** | Compilation Firewall | session — the AnalysisSession Facade | give AnalysisSession a single unique_ptr<Impl> holding ExecutionCore, TimelineManager, transparency chain, macro engine, script VM, decompiler and introspection, so the session header needs only <memory> and pulling in shell/apps does not transitively drag in Capstone/Ghidra/Luau/LibVMI headers; the right firewall for the non-polymorphic aggregating Facade (the swappable backends already use the abstract-interface-plus-factory firewall). |

AVOID while the shell stays a line REPL — the Observer event bus plus the AnalysisSession Facade already carry all cross-subsystem talk and a Mediator would just be a redundant god-object; it only earns its place once genuine many-to-many widget coupling appears. |
| **Reactor** | POSA2 Event Handling | shell — the CLI front-end input loop | a small demultiplexer waits on stdin (typed commands) and a pipe/eventfd the engine thread signals when an Event or run-completion is ready, dispatching each synchronously on the shell thread so the prompt stays live during a run; a deliberately lightweight realization — a full Reactor framework is overkill for two local sources, so this stays optional. |
| **Proactor** | POSA2 Event Handling | replay — TimelineManager snapshot persistence (disk streaming) | only if sparse full-snapshots are streamed to/from disk, issue them as OS async I/O (io_uring) and dispatch each completion to a handler that links the blob into the ring buffer so no thread blocks on disk during a long recording; in-process async work (decompile, introspection) is already covered by Active Object + Future, so Proactor earns its place only for genuine OS-level async I/O — otherwise skip it. |
| **Double-Checked Locking** | POSA2 Synchronization | decompiler/introspection — lazy Ghidra-JVM and LibVMI backend init | the Ghidra backend (and LibVMI handle) is expensive and wanted only on first use, so initialize it lazily and share it via std::call_once / a function-local static — which the standard already makes thread-safe — rather than a hand-rolled double-checked lock, the classic bug-prone anti-pattern; that is why this is optional and not a build-it-yourself item. |
| **Policy-Based Design** | Compile-time Composition | replay — the TimelineManager retention axes | ADD (narrow): template<EvictionPolicy, SnapshotSpacingPolicy, StoragePolicy> would fuse the retention knobs with zero indirection, but in a time-travel shell those knobs (buffer depth, snapshot interval) are things the analyst tunes at run time, so runtime Strategy usually fits better; reserve policies for a truly build-time inner axis (the page-diff/compression codec used when writing a memento) — otherwise it is Strategy wearing a template hat. |
| **Tag Dispatch** | Compile-time Dispatch | common — GuestMemory::read_int/write_int little-endian codec and memento (de)serialization | ADD (narrow): dispatch the fixed-width paths on std::integral_constant<unsigned,N> to emit unrolled branch-free little-endian loads/stores instead of the runtime 'bytes' switch; honest reach — the dominant dimensions (Width, OpKind, Arch) are decoded from guest bytes at run time, so this cannot touch the interpreter's main decode/execute switch and only pays off in the handful of compile-time-sized codec helpers. |
| **Attorney-Client** | Encapsulation / Access Control | core StateMemento and common MemorySnapshot friendships | ADD (deferred): the current single-friend design is clean because exactly one Originator touches each opaque snapshot; Attorney-Client earns its place only when a second partially-trusted collaborator appears — e.g. a MementoSerializer needing read-only byte access for on-disk timeline persistence — when you expose a MementoAttorney forwarding just the serialization slice rather than friending the whole replay library. Add it when that collaborator arrives, not before. |
| **Data Mapper** | Fowler PoEAA | session/replay/macro — saving and loading sessions and macros | a SessionSerializer / MacroSerializer maps domain objects (recorded Command lists, the injected-event log, run-points, CpuState) to and from an on-disk format with no serialize() methods intruding on the domain types, letting analysts save, reload and share reproducible sessions; deferred to optional because it is orthogonal to the time-travel engine and adds no capability the engine needs to function. |

## Deliberately avoided (6)

Applying these here would be cargo-cult; the reasoning is recorded so a future
change does not reintroduce them by reflex.

| Pattern | Why not |
|---|---|
| **Singleton** | AVOID: a global ExecutionCore, TimelineManager or config makes concurrent analyses impossible and silently breaks the deterministic-replay tests that depend on fully isolated per-session state; nothing needs a process-global (Capstone/Luau/LibVMI handles are per-object, Ghidra is a separate process). The one tolerable micro-use is the static map behind a self-registration Registry reached only at static-init — use DI of a single owned instance everywhere else. |
| **Monostate** | AVOID, worse than Singleton because it is hidden: Monostate would smuggle process-wide mutable state into subsystems that must be per-session and bit-for-bit deterministic, so two AnalysisSessions would silently alias state and corrupt each other's timelines; if a shared feature-flag/config is needed, inject an immutable config value object per session instead. |
| **Leader/Followers** | AVOID: it optimizes a pool sharing one high-frequency, multi-source handle set (a network server's sockets) by rotating which thread demuxes; dede has no such shared handle set — only discrete coarse analysis jobs and a single deterministic vCPU — so a plain Thread Pool with a work queue is simpler and strictly sufficient, and Leader/Followers here would be cargo-cult complexity for zero throughput benefit. |
| **Broker** | AVOID as the design stands: dede is a single in-process shell, IExecutionBackend is plain runtime polymorphism, and MemoryProxy is a GoF Proxy over local memory — none is a Broker and there is no remoting to mediate. It earns its place ONLY if emu_host were split into a separate sandboxed process running Unicorn/KVM, when a proxy/stub pair would marshal step/read/write/snapshot across the boundary; do not add it until that boundary exists. |
| **Expression Templates** | AVOID: dede has no elementwise array/matrix arithmetic or temporary-heavy numeric chains, which is the entire reason expression templates exist; the nearest candidate (a fluent mov(rax, imm(0x10))) has no lazy-evaluation/temporary-fusion problem and is covered by the Builder/Fluent idiom, so ET here would be pure cargo-cult complexity (opaque types, brutal compile errors) for no measurable win. |
| **Barton-Nackman Trick** | AVOID in C++20: the whole motivation (1994 template-overload ambiguity) is obsolete; use auto operator<=>(const T&) const = default; / bool operator==(const T&) const = default; directly on each value type for all six relational operators with less code and far clearer errors than a Comparable<T> CRTP base — reach for defaulted <=>, do not resurrect Barton-Nackman. |
